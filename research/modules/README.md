# research/modules/

Sprint 2 research done specifically to support a white paper module — once
the lifecycle map has named the stages, this is where research targeted at
a particular stage (rather than general AI-in-SDLC reading) gets captured
before it's written up as a module.

## What belongs here

- Captures (using [../ai-in-sdlc/TEMPLATE.md](../ai-in-sdlc/TEMPLATE.md))
  gathered specifically to answer an open question in one
  `white-paper/modules/` file
- Named after the lifecycle phase they support, e.g. `code-review.md`,
  `deployment.md`

## What does not belong here

- General AI-in-SDLC research not tied to a specific module — that goes in
  [../ai-in-sdlc/](../ai-in-sdlc/)
- The module content itself — that goes in
  [white-paper/modules/](../../white-paper/modules/), which follows
  [white-paper/modules/TEMPLATE.md](../../white-paper/modules/TEMPLATE.md)
  and cites this research rather than duplicating it
- Synthesized, cross-source conclusions — those go in
  [../ai-in-sdlc/synthesis.md](../ai-in-sdlc/synthesis.md)

## Note

`Module_Template.md` in this folder is an earlier draft of the module
write-up format, superseded by
[white-paper/modules/TEMPLATE.md](../../white-paper/modules/TEMPLATE.md).
Use the `white-paper/modules/` template for actual module files; this one
is kept for reference only.

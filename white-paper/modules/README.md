# white-paper/modules/

One file per SDLC stage (e.g. planning, coding, code review, testing,
deployment), each following `TEMPLATE.md`.

## Important: stage names are not decided yet

Stage files are created once the lifecycle map (authored on Miro, see
[design/lifecycle-map/](../../design/lifecycle-map/)) names the stages in
Week 2. **Do not invent stage names or create stage files ahead of that.**
Until then, this folder should only contain this README and the template.

## What belongs here (once stages are named)

- One markdown file per stage, named after the stage (e.g.
  `code-review.md`), filled out using `TEMPLATE.md`

## What does not belong here

- Raw research behind a stage's content — that goes in
  [research/](../../research/) and gets cited from the module
- Governance or cross-cutting policy — that goes in
  [governance/](../governance/)
